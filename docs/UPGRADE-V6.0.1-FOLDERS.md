# V5.6 文件夹扩展版 → V6.0.1 兼容版升级指南

本文针对你已确认的线上版本：`VERSION = 1532-folders-1`、已安装文件夹功能、使用本地存储。可直接升级，无需先安装 V5.7。

目标基于官方 V6.0.1：`ac4a8fa6d50a239503c0a4a8c56c8574a9aa16c6`。兼容版标识为 `1541-folders-3`，独立扩展标记为 `601-1`。前后台采用你已确认接受的 Vue/Nuxt 新界面。

## 本次与上次 V5.7 升级的重要区别

**本次必须执行专用兼容迁移，不能只覆盖程序，也不能按“数据库无需升级”操作。**

官方 V6 的数据库版本也是 `1002`，但它表示新增存储管理。你的旧定制版 `1002` 表示文件夹扩展。直接使用官方升级器，会误判“已经是最新版本”，跳过存储迁移。

本包的 `admin/upgrade.php` 根据实际表结构补全迁移，保留已有目录数据，并另用 `pre_config.folder_extension = 601-1` 标记完成。原生 `pre_config.version` 仍为 1002，**不要手动修改版本号来绕过迁移**。

## 已保留的功能

- 管理员统一管理多层目录：新建、重命名、单个/批量移动及空目录删除。
- 文件和文件夹的置顶/取消置顶；每目录独立的手动、名称和时间排序。
- 先置顶、再普通；组内文件与文件夹混排，数字越小越靠前，不设文件夹优先。
- 原有目录层级、文件归类、排序数字、置顶状态、用户、密码、隐藏状态、hash 和外链。
- 文件移动仍只修改分类，不搬动磁盘上的文件；新上传默认归入根目录。
- “我的文件”沿用 V6 的用户文件列表与批量功能，不开放管理员目录操作。
- 新版存储管理及 V6 原有功能。你的旧本地存储会登记为一个存储位置，旧文件通过 `storage_id` 关联它。

公告使用 V6 原有展示方式。此前讨论的“自定义首页公告弹窗”仍为待开发需求，本次没有额外实现。

## 一、备份和确认存储位置

1. 开启维护模式，暂停网页/API 上传、后台写入，允许管理员自己的 IP 访问升级入口。
2. 备份完整数据库和整个站点，并确认备份成功。备份放到网站根目录以外。
3. 在旧站后台确认本地存储路径：未填写时，文件在旧站根目录的 `file/` 中；填写了自定义路径时，记录并完整保留那个目录。
4. 本指南采用**在原网站根目录升级程序**的方式，使默认 `file/` 的绝对位置保持不变。不要同时更换网站根目录或搬动上传目录。若要换目录，必须先安排原文件路径映射，不能直接套用本步骤。
5. 网站 PHP 必须 >= 8.1，启用 PDO MySQL、cURL、GD 及站点需要的其他扩展。已编译好前后台、已打包 PHP 依赖，服务器不需要 Node.js、pnpm 或 Composer。

升级前可在 phpMyAdmin 执行以下**只读查询**，记录结果：

```sql
SELECT v FROM pre_config WHERE k='version';
SELECT COUNT(*) AS file_count FROM pre_file;
SELECT COUNT(*) AS folder_count FROM pre_folder;
SELECT COUNT(*) AS user_count FROM pre_user;
SELECT v FROM pre_config WHERE k='filepath';
```

## 二、替换程序，保留配置、文件和安装锁

V6 已替换整个前后台并将依赖搬到根目录 `vendor/`，因此不建议把新旧程序长期混放。

在维护模式下、完成整站备份后：

1. **保留在原位置：** `config.php`、`file/`、实际自定义存储目录、`install/install.lock`，以及你自己的 Web 服务器配置。
2. 将旧的 `admin/`、`assets/`、`includes/` 程序目录移到站点以外的备份位置。如果以前存在根目录 `vendor/`，也先移出，使用本包完整替换。如果旧 `frontend/` 仅为源码，可以同样移出。
3. 旧根目录程序文件会被新版同名覆盖。若根目录有旧 `index.html`，先移出，避免服务器优先打开旧页面。
4. **若真实上传目录位于上述程序目录内部，必须先保留该上传目录并核对其路径，不可直接移走整个父目录。** 默认 `file/` 不受上述程序目录清理影响。
5. 解压 `WangPan-V6.0.1-folders-v3-upgrade.zip`，将 **`upload/` 内部全部内容**上传到原网站根目录。必须完整上传 `admin/assets/_nuxt/`、`assets/_nuxt/` 和根目录 `vendor/`，不要只挑 PHP 文件。

示例：`upload/admin/upgrade.php` 对应网站的 `admin/upgrade.php`，不能上传成网站里的 `upload/admin/upgrade.php`。

包不包含线上配置、上传内容或安装锁，不包含全新安装 SQL。包里的 `source/` 是前端源码和测试资料，**不用上传到网站**。

不要在新版之上重新覆盖旧 V5.6/V5.7 定制包；不要删除安装锁；不要重新安装网站或导入 `install/install.sql`。

## 三、运行专用兼容升级

1. 访问 `https://你的域名/admin/upgrade.php`。
2. 原管理员 Cookie 有效时可以直接使用。若提示未登录，先在同一浏览器打开新版后台 `https://你的域名/admin/#/login`，用原管理员账号登录；完成后手动回到 `admin/upgrade.php`。
3. 子目录安装时加上前缀，例如 `https://你的域名/pan/admin/upgrade.php` 和 `/pan/admin/#/login`。
4. 勾选“已备份完整数据库和网站文件，并暂停上传及后台写入”，执行增量升级。
5. 等待出现“兼容升级完成”。迁移会检测并保留已有目录，补全 `pre_storage`、`pre_file.storage_id` 及索引，将旧存储设置登记并关联旧文件，然后写入独立扩展标记。
6. 不需要手动导入包中的 SQL。本包的 `/install/update.php` 会跳转到安全的兼容升级入口，不再使用官方按数字版本判断的迁移逻辑。

原本地存储为默认路径时，新存储仍指向同一网站根目录的 `file/`；自定义路径会按原配置保留。迁移**不复制、不删除、不重命名上传文件**。

如果原路径不可访问、SQL 权限不足、操作超时或其他错误：保持维护模式，检查报错及服务器日志。修复路径/权限后可重试；成功前不会写入 `601-1` 完成标记。不要并发反复点击，也不要强行写版本号来跳过检查。大表新增字段/索引可能耗时，需确认数据库操作是否仍在执行。

升级后只读复核：

```sql
SELECT k,v FROM pre_config WHERE k IN ('version','folder_extension');
-- version = 1002；folder_extension = 601-1
SELECT COUNT(*) AS file_count FROM pre_file;
SELECT COUNT(*) AS folder_count FROM pre_folder;
SELECT COUNT(*) AS user_count FROM pre_user;
SELECT id,name,type,isdefault,status FROM pre_storage;
SELECT COUNT(*) AS unmatched_files
FROM pre_file f LEFT JOIN pre_storage s ON f.storage_id=s.id
WHERE s.id IS NULL;
-- unmatched_files 应为 0
```

## 四、刷新和上线验收

重载网站 PHP / 清理 OPcache，浏览器强制刷新。V6 前台和后台改为 hash 路由，例如 `/#/upload`、`/admin/#/file`。旧文件下载/预览外链仍保留 PHP 路径。

验收时至少检查：

1. 文件、文件夹、用户数量与备份前一致，目录层级和旧的排序/置顶状态保留。
2. 首页与后台可逐级进入目录，面包屑可返回上级，PC/手机均正常。
3. 同目录中一个文件数字 1、一个文件夹数字 5，确认文件在前；置顶组也按数字混排。
4. 新建、重命名、移动、批量移动、规则排序保存和置顶/取消置顶可用。非空目录拒绝删除。
5. 旧下载链接、旧预览链接、有密码的链接可用；隐藏文件仍不公开。
6. 移动一个测试文件后，用**同一个旧链接**下载并核对内容。
7. 网页/API 新上传、原用户登录及“我的文件”正常。
8. 后台存储管理显示本地存储；默认位置和自定义路径与旧站一致。

通过后再关闭维护模式。大版本界面更换后建议清理代理/CDN 页面缓存和旧静态资源缓存。

Apache 可参考包中的官方 `.htaccess`。Nginx 的路径保护需要在原站配置中保留/补充，例如根路径部署时：

```nginx
location ~ ^/(vendor|file|includes)/ {
    deny all;
}
```

子目录部署应相应调整前缀。此规则限制直接访问存储和依赖目录，不阻止 `down.php`、`view.php` 正常读取文件。

## 五、回退

在验收完成前保持暂停写入。需要回退时，恢复升级前同一时点的完整程序和数据库备份，恢复原 `config.php` 与安装锁，文件目录保持原位置；清理 OPcache 后验证旧链接。

如果升级后已有新增上传/修改，先另行保存这些增量，再处理回退，不能直接用旧数据库覆盖。若在 V6 新增了其他存储位置，旧版不认识多存储关联，不能只换回旧页面。应先确认新增文件归属及增量迁移方案。

## 六、验证与维护

本地验证环境 PHP 8.2.28、MariaDB 10.11.11，前端使用官方锁定依赖并重新编译。已通过 38 项迁移/数据服务检查、26 项 HTTP 检查、20 项 PC/手机浏览器检查。浏览器没有 JS 异常或资源加载失败；检查包含旧定制版1002冲突、数据保留、迁移重试、本地路径保留、原下载内容、密码保护和新界面实际管理操作。

这些是独立测试环境的验证，未连接或改动你的线上数据库。正式更新前仍应按本文备份、预演并验收。

PHP 源码在 `upload/`，Nuxt 修改后的可维护源码在 `source/frontend/`，已编译页面及资源也在 `upload/`。本地维护时，先新建项目目录，将 `upload/` 内容放入其中，再将 `source/frontend/` 复制为该项目的 `frontend/`；测试资料可复制为项目的 `tests/`。这样构建脚本才会将产物输出到正确的前后台目录。

以后修改前端，需要在本地配置合适版本 Node.js（本次24.11.1）和 pnpm，按前端 `package.json` 的 build 脚本重新编译，不能只修改 `.vue` 后直接上传。测试脚本只可连接独立测试库，不能连接线上数据库。
